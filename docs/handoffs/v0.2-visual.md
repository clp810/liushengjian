# v0.2 视觉任务交接：DeepSeek → 主线

状态：任务书已准备；视觉原型待制作、用户待确认，尚未进入正式应用。

## 目标与分工

为「留声间」制作一份可在浏览器打开的独立视觉原型，重点是唱片墙和预设封面选择。
DeepSeek 负责原型与设计说明；用户确认视觉方向；主线负责接入真实收藏、音视频播放、测试与版本发布。

留声间的特点是收藏不同现场、翻唱及演绎版本，保留来源与个人笔记，拥有自己的听歌空间。
v0.2 计划包括唱片墙、现成艺术封面、本地 Live 视频。当前任务只负责视觉原型。

## 视觉方向

- 主体是有秩序、以封面为中心的唱片墙，参考 Folia 的空间层次、留白和沉浸氛围，自行设计实现。
- 轻微透视、柔和阴影、聚焦时浮起；封面保持易读，不依靠夸张三维效果。
- 保留「留声间」自己的名称、文字和收藏气质，不使用 Folia 品牌或直接搬运其源码、素材。
- 展示歌名、演唱者、现场／翻唱版本标签；选中时能看到来源、收藏笔记和是否有视频。
- 点击封面进入播放预览，可以有轻量放大和背景变暗的过渡；播放、返回和全屏入口易于发现。
- 搜索、心动、排序、添加收藏的位置清楚；不能只有鼠标悬停才能操作。

## 必须交付的画面与交互

1. 唱片墙：使用 12–20 张虚构收藏展示不同文字长度与封面；提供空收藏状态。
2. 封面选择：原始封面、艺术封面、自己上传三个入口；做 3–4 套现成艺术风格及选中预览，可跳过、可重选。以本地 HTML/CSS/SVG 绘制示例，不调用付费生成服务。
3. 听音室视觉预览：从墙面进入、返回；展示「收听／观看现场」两种布局，以及仅有音频的状态。视频区域使用明确的演示占位。
4. 本任务只模拟界面状态；在原型中标明演示性质，不宣称真实导入、上传、下载或播放成功。

## 文件范围与实现方式

- 所有新增或修改文件只放在 `design/v0.2-visual/`，包括原型、静态素材、截图和交接记录。
- 推荐入口 `index.html`，配合独立 CSS、JavaScript 与本地素材；沿用原生前端方式，无需 Node 构建或新增依赖。
- 不修改 `app/`、数据库、依赖配置、版本号、根目录规则或主线状态文档；不创建版本标签、不合并主线。
- 不读取或修改 `data/`、`outputs/`、`.cache/` 中的真实收藏与媒体，也不连接留声间真实服务或账号。
- 原型应可离线浏览；所有样例为虚构数据，不引入外部图片、字体或服务依赖。
- 若启动预览服务，仅绑定 `127.0.0.1`，使用独立空闲端口。入口和预览方法写入原型 README。

## 验收与交接

- 检查桌面约 1440 px 和窄屏 390 px：封面与文字无明显截断，页面无意外横向溢出。
- 验证选中收藏、封面预览、进入与返回听音室的演示交互；键盘可操作，尊重减少动态效果的系统偏好。
- 保存代表性的桌面、窄屏截图；能实际运行的检查才标为通过，无法执行的检查如实记录。
- 写 `design/v0.2-visual/HANDOFF.md`：设计取舍、预览入口、修改文件、已验证、未验证、模拟功能、接入建议、可直接复用的样式或模块。
- 只暂存本任务目录，检查后提交到任务分支；在完成回复中给出分支名、完整提交号、工作目录和交接记录路径。
- 若不能使用 Git，保留完整文件并明确说明“未提交”；主线会检查后接收。

主线接收后先审查原型与改动范围，再交由用户确认视觉；接入真实功能后运行项目要求的测试，整体完成时提交并创建 `v0.2.0` 标签。原型完成不代表 v0.2 已发布。
